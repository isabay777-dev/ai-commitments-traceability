# Frozen outcome rule F4 (harmonisation review) — fixed 2026-10-11 before any re-review output was seen

Purpose: apply ONE evidential standard to all 184 commitments in F3, including cases where two coding rounds agreed.
Core principle: an outcome above not_fulfilled requires evidence of an ACHIEVED STATE (launched, deployed, operating, in use, completed, rolled out, piloted/tested in live operation) for the SAME promised object/function. Activity verbs alone (developing, working on, progressing towards, preparing, continuing development, planning, on track, positioned to deliver) never count as achievement.

- fulfilled: a later report states that the promised object/function is implemented/launched/in use at the explicitly promised scale. If the commitment was to run a study, pilot or test, completion (or live operation) of that study/pilot suffices. For a broad general-AI commitment, at least one named, implemented AI process consistent with the commitment's scope is required; repeating the strategy is not enough. Scope or deadline not stated in the original is not invented.
- partial: achieved-state evidence for the same object but incomplete: a live pilot where full deployment was promised; some of the promised functions live; a smaller scale, one unit, one market, one product line.
- not_fulfilled: the same object reappears but only as ongoing work, development, testing without a live pilot, renewed plan, postponement, or explicit cancellation.
- dropped: no identifiable continuation of the commitment located in the available later reports (not a synonym for cancellation).
- not_a_promise: the original fragment is not a company undertaking to implement AI.
Deadlines are recorded separately; a future deadline is not a failure. First year = first later report year with achieved-state evidence meeting the assigned category.
