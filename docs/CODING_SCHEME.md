# Схема кодирования фрагментов об ИИ (v0.1, 30.09.2026)

Единица кодирования — фрагмент: предложение, найденное словарём ИИ (`scripts/textutil.py`), плюс по одному соседнему предложению до и после.

## 1. Относится ли к ИИ (фильтр)
- `0` ложное срабатывание (не про ИИ; «AI» как аббревиатура другого).
- `1` про ИИ.

## 2. Тема (одна основная)
| Код | Тема | Пример |
|---|---|---|
| STR | Стратегия, цели, приоритеты | «Мы усиливаем фокус на технологиях ИИ» |
| APP | Применение в собственной деятельности | «ИИ-модели в кредитном скоринге» |
| PRD | ИИ в продуктах и услугах для клиентов | «Виртуальный ассистент на нашем ИИ» |
| RSK | Риски, регулирование (AI Act), этика | «Риски, связанные с ИИ» |
| GOV | Управление ИИ: политика, комитет, дорожная карта, ответственные | «Дорожная карта проектов ИИ, утверждена советом директоров» |
| INV | Инвестиции, партнёрства, покупка решений | «Партнёрство с поставщиком разговорного ИИ» |
| ENV | Внешний тренд, рынок, отрасль | «ИИ меняет отрасль здравоохранения» |
| HR | Кадры, обучение, навыки | «Курсы "ChatGPT как ежедневный помощник"» |

## 3. Конкретность (главная зависимая переменная)
- `0` Общее: без названного процесса, срока, результата или объекта.
- `1` Частично конкретное: назван процесс или область применения, но нет статуса, срока или результата.
- `2` Конкретное: названы процесс **и** хотя бы одно из: статус внедрения (пилот/внедрено), срок, количественный результат, сумма, наименование решения или партнёра.

## 4. Статус (только для APP/PRD/INV)
`PLAN` план · `PILOT` пилот · `LIVE` внедрено · `NA` не указано.

## Переменные уровня отчёта
- `ai_any` — есть хотя бы один фрагмент с кодом 1.
- `ai_per_1000` — фрагменты ИИ на 1000 предложений повествовательной части.
- `ai_specific` — число фрагментов с конкретностью 2.
- `ai_depth` — 0–8 по четырём направлениям (STR, APP/PRD, RSK/GOV, INV): 0 — нет, 1 — общее, 2 — конкретное.
- `ai_generic_share` — доля фрагментов с конкретностью 0 (не определена, если фрагментов нет). **Не называть это AI washing.**

## Валидация
- Два независимых кодировщика на стратифицированной подвыборке (страна × год × язык), 600–1 000 фрагментов; включить случайные предложения, которые словарь не нашёл, чтобы оценить полноту.
- Отчитываться: precision/recall по языкам, каппа Коэна и Gwet AC1.
- PL валидирует польский соавтор; KZ (RU/KZ) — первый автор; NL — второй кодировщик.

## Известные технические проблемы
- `pdftotext -layout` склеивает колонки, и предложения рвутся. Для кодирования извлекать без `-layout` и резать на предложения заново.
- Отчёты сильно различаются по длине — нормировать.

# v0.2 (05.10.2026): поля для статьи №1 (обещания и выполнение) и статьи №2 (источник ИИ)

Одна строка на фрагмент, разделитель `;`:
`fragment_id;is_ai;topic;specificity;status;promise;use_case;source;note`

- `is_ai`: 1 — про ИИ, 0 — ложное срабатывание.
- `topic`: STR / APP / PRD / RSK / GOV / INV / ENV / HR (см. v0.1).
- `specificity`: 0 / 1 / 2 (см. v0.1).
- `status` — что компания говорит о СВОЁМ ИИ: `PLAN` (намерение, «планируем», «будем»), `PILOT` (тест, пилот, PoC), `LIVE` (внедрено, используется, есть результат), `NA` (не о своём ИИ: тренд, риск в общем, регулирование).
- `promise`: `yes` — компания берёт на себя будущее обязательство по собственному ИИ (PLAN или PILOT с намерением масштабировать); иначе `no`.
- `use_case` — короткая метка применения по-английски, 2–5 слов, для прослеживания по годам: например `credit scoring`, `customer chatbot`, `predictive maintenance`, `document processing`, `fraud detection`, `demand forecasting`, `code generation`, `general AI strategy`. Для `status=NA` — `NA`.
- `source` (для статьи №2): `own` (собственная разработка или собственная команда), `external_dev` (заказная разработка или доработка внешним разработчиком), `off_the_shelf` (готовое коммерческое решение, например Copilot или ChatGPT Enterprise), `partnership` (совместно с партнёром, вузом или стартапом), `unclear`, `NA` (не о своём ИИ).
- `note` — до 120 знаков, без `;`.

Выполнение обещания (статья №1) считается позже по панели: обещание `(firm, use_case)` со `status=PLAN/PILOT` в году t → выполнено, если в t+1…2025 у той же фирмы есть `status=LIVE` с тем же или близким `use_case`.

## Уточнения v0.2.1 (после пробы на 100 фрагментах)
- Глоссарий, список сокращений, оглавление, повтор заголовка без содержания → `is_ai=0`.
- Нечитаемый текст (сбой кодировки PDF) → `is_ai=0`, в `note` написать `garbled`.
- `specificity` оценивает только то, что сказано о СОБСТВЕННОМ ИИ компании. Подробный пересказ закона (AI Act) или рыночного тренда — не выше 1. Общее намерение «инвестировать в ИИ и аналитику» без названного процесса — 1, не 2.
- `promise=yes` только для обязательств компании внедрить, использовать или масштабировать ИИ в своей деятельности или продуктах. Намерение обучить совет директоров или сотрудников ИИ-компетенциям — `topic=HR` или `GOV`, `promise=no`.
